# LevelSync — every character at your highest character's level (BepInEx 5)

The XP counterpart of SharedFortunes. Whatever your highest campaign character's level is, every other character you own is raised to it: existing ones when they load, and the rest of your party live as one of them earns XP. Skill points and stat points come with the level, because the game computes unspent points from level rather than handing them out one at a time. Levels are never lowered.

- **Pool:** the highest `ExperienceLevel` (level plus progress into it) across your `CharacterN.json` saves, scanned at startup and on F9, kept current from XP gains while playing, and mirrored to `LevelSync.json` next to the saves for visibility.
- **On load** a lower character is raised to the pool level (capped by `MaxLevel`). Health and mana keep their percentages, exactly as a normal level-up does.
- **While playing**, after a reward hands out XP, every other character in your party that you own is raised to the pool on the next frame. Waiting one frame matters: the game gives XP to party members one after another, so raising the others mid-hand-out would stack the same reward several times (a party of three would earn triple XP). Each member still earns exactly its own share; the sync only tops up whoever ended lower.
- **New characters** are left alone on the creation screen and synced the first time they load into a session.
- Roguelike characters are excluded by default (`IncludeRoguelikeCharacters`), since that mode levels per battle.
- Purely local: it reads your own saves and only ever changes level through the game's own save routine. Friends who install it sync their own characters.

Config: `BepInEx\config\stolenrealm.levelsync.cfg` (F9 in game reloads it and rescans the saves). Master switch: `LevelSync = true/false` in `stolenrealm.mods.cfg`.

| Section | Key | Default | What it does |
|---|---|---|---|
| `1.Sync` | `Enabled` | true | Master switch inside the mod. |
| `1.Sync` | `IncludeRoguelikeCharacters` | false | Sync Roguelike characters too. |
| `1.Sync` | `MaxLevel` | 30 | Never raise above this. |
| `2.General` | `ReloadKey` | F9 | Re-read config, rescan saves. |
| `2.General` | `VerboseLogging` | false | Log every check and raise. |

## How it works

`Character.Level` is `floor(ExperienceLevel)`; `UnspentSkillPoints = Level - 1 + 3 - spent` and `UnspentStatPoints = creationStatTotal + (Level - 1) x NumStatsPerNewLevel - spent`, so setting `ExperienceLevel` is the whole job. Three Harmony patches (`src/Patches/LevelPatches.cs`):

1. `Character.Load(int saveIndex)` (existing saves only, `saveIndex >= 0`): offer the character's level to the pool, then raise it if the pool is higher.
2. `Character.GiveExperience`: offer the new level to the pool and flag a party sync; the plugin's next `Update` (`LevelPatches.Tick`) raises every owned, eligible character in `NetworkingManager.Instance.MyPartyCharacters` that is below the pool. Deferred on purpose (see above).
3. `Character.Save` prefix (only once the character `IsLoaded` and not on the creation screen): catches a brand-new character on its first save after creation.

Only characters you own (`Character.Owned`) can feed or take from the pool, so a friend's higher-level character in your co-op party never changes yours. The Load postfix runs at high Harmony priority so SharedFortunes, which caps shared fortunes to the character's level, sees the raised level. The `[HarmonyPriority]` attribute sits on the `Postfix` method itself: the Harmony build BepInEx ships silently drops a class-level priority (verified), which would leave all the Load postfixes running in plugin load order.

A raise copies what `GiveExperience` does after a level change: capture health/mana ratios, set `ExperienceLevel` (which queues the game's save), flag `JustLeveled`, `MaxVariableAttributeChange("Health"/"Mana", ratio)`, `QueueCharacterSave()`.

## Rebuild

```
cd mods\LevelSync
dotnet build -c Release
```

Same setup as SharedFortunes (references `Newtonsoft.Json.dll` from the game folder for `CharacterSaveFile`). Follows the master-config pattern: `src/MasterConfig.cs` and `src/Plugin.cs` are generated by `tools/gen_master.py`.
