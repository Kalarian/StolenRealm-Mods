# QoL — cheaper item upgrades (BepInEx 5)

Config: `BepInEx\config\stolenrealm.qol.cfg` (F9 in game reloads it). Master switch: `QoL = true/false` in `stolenrealm.mods.cfg`.

| Section | Key | Default | What it does |
|---|---|---|---|
| `1.ItemUpgrade` | `CostByLevelGap` | true | Noor's item upgrade costs only the price difference between the item's current level and your level, instead of the full price at your level. Topping up every few levels then costs the same overall as one big jump. |
| `1.ItemUpgrade` | `CostMultiplier` | 1.5 | Multiplier on that difference (vanilla uses 1.5 on the full price). |
| `3.General` | `ReloadKey` | F9 | Re-read the config. |
| `3.General` | `VerboseLogging` | false | Log each upgrade cost computation. |

This plugin also stamps the log with the Windows user, machine and (once Steam is up) the Steam name and SteamID, so a friend's `LogOutput.log` says whose it is (`src/LogOwner.cs`). The `SESSION START` line is printed by whichever of our plugins loads first (shared `MasterConfig.LogSessionStartOnce`, AppDomain-flagged), so it always precedes every mod's startup lines.

Install: `stolenrealm.qol.dll` goes in `BepInEx\plugins\QoL\`. Client-side; other players unaffected.

## How it works

Harmony postfix on `ItemUpgradeManager.GetUpgradeCost` (with a prefix on `UpgradeItem` to capture the pre-upgrade level, since the game raises the item level before charging). The same value feeds the displayed price, the affordability check and the charge.

**Removed 2026-09-15:** the "Treasure Chest event" feature. It changed the event's `rarity`, but the game only uses `rarity` to weight *lesser* events; the Treasure Chest events are major events drawn by `ChanceRatio` (1.0, like every other treasure-node event) and already spawn in vanilla. The patch never did anything.

Follows the master-config pattern: `src/MasterConfig.cs` and `src/Plugin.cs` are generated by `tools/gen_master.py`.
